# Brand, projects, and workflow contract scenarios

These are realistic baseline cases for an agent trace or mocked connector. Use current generated schemas, not historical tool counts. They do not authorize live writes, credit use, or external sends during a documentation audit.

| Scenario | Expected behavior | Failure to catch |
|---|---|---|
| “Audit Acme in the Marketing teamspace. Do not change anything.” | Resolve Marketing to numeric `space_id`, list/select kit, get with `expand: "extra,website"`, inventory and read context, inspect ICP/pillar adapters; all downstream tool calls carry scope. Report evidence and gaps. | Writes, incomplete scope, treating list summaries as full context. |
| “Create Acme from this supplied identity, voice, two ICPs, and three pillars.” | List to avoid duplicate, create title, build supplied identity plus strict `icps`/`content_pillars` arrays, create ordinary voice context, read back. Proceed from explicit instruction without another approval. | Creating canonical pillars as KnowledgeDoc; inventing hex codes; missing strict array requirements. |
| “Add this pillar to our current brand; preserve the rest.” | Read current evidence, send `content_pillars` objects with name/description and supported optional keys to build. Read rendered adapter. Omitted pillars survive. | Passing adapter output to `api_updateContextDocument`; unknown fields; empty array deletion. |
| Pillar adapter returns 404 while legacy pillar context exists. | Recognize structured/legacy difference, inventory legacy links and explain the existing evidence. Canonical structured writing follows authorized scope. | Assuming no context exists and creating another competing KnowledgeDoc. |
| “Revise this existing brand voice and remove the obsolete examples document.” | Read exact records, update voice using `brand_id` and resolved `document_link_id`; remove the exact authorized obsolete link, explain orphan cleanup consequence. | Reconfirmation despite explicit targets; updating wrong ID or an adapter; unrequested deletion. |
| “Create an Autumn Launch creative project with these six deliverables.” | Resolve scope, create `Project`, use asset UUIDs, ISO date-times, short status and integer priority; record owner/dependency metadata honestly. Verify returned deliverables. | Unneeded inventory of an empty project; native PM ownership claims. |
| “Mark the hero image approved and attach this generated asset; keep our other campaign state.” | Read project item, merge entire existing `data`, call `api_updateProjectItem` with `resourcetype`, `parent_lookup_project_id`, item `id`, and scoped fields. | Replacement of unrelated data; duplicate creation instead of PATCH. |
| “Create a Kanban board with subtasks and dependencies.” | Route to `simplified-project-management` and `pm_*`, keeping PM IDs distinct from creative project items. | Treating Project metadata as native team planning. |
| “Assign this known agent to that deliverable, then export the approved article to partner 123.” | Resolve exact UUIDs/IDs and authorized scope. Assign only the specified item, export only selected article using project `id`, numeric partner and UUID list; report initiation separately from completion. | Extra routine approval; claiming completion from assignment/export acceptance; invented partner discovery. |
| Public root connector exposes project tools but no `flows_*`. | Explain automation connection requirement at `/automation/mcp`; do available discovery without claiming installation grants missing tools. | Calling unavailable namespace or pretending resources exist. |
| “Build and publish an input-to-draft-text workflow.” | Read authoritative grammar, discover current actions, author both input declaration places and diagram, preserve full extra, publish. Test only if test scope authorized; no external sends. | Routine pre-authoring approval; unsolicited credit-spending test; writing conductor directly. |
| Client has no resource reader and no accessible grammar copy. | Use tool discovery/status where possible and report authoring reference limitation. | Guessing diagram grammar and publishing fabricated graph. |
| “Run this known workflow with these exact inputs.” | Read input schema and diagram in selected scope; start once within authorized effects, stable idempotency key for uncertain retry, retain UUID returned as `workflow_id`, poll using `run_id`. | Using numeric definition as run ID; duplicate runs; injecting context. |
| “Approve the review step in this waiting run.” | Read status with tasks, identify actual waiting task, call approve with `task_reference_name` copied from response `reference_task_name`, `COMPLETED`, correct run and scope. | Wrong parameter name; blanket gate release; unnecessary approval loop. |
| “Fix the graph and rerun the failed run.” | Read/merge diagram, publish fix, restart with `useLatestDefinitions: true`; explain repeated effects within user scope. | Restart defaults to old definition. |
| “The original run had the wrong input; run it with this corrected input.” | Start a new run with corrected `input` and its own idempotency key. | Restart reuses original wrong input. |
| Action has selectAsync style field; palette transiently returns 503. | Bounded retry, `page_size <= 100`, resolve options via verified relative path and passthrough query, inspect `{status,body}`. | Invented choices; endless retries; full URL/credentials in passthrough. |

Local audit validation: instantiate `create_server(token="dummy", profile=...)`, inspect `get_tools()`, `get_resources()`, and `get_resource_templates()` without dispatching calls. Public exposes brand/project tools but excludes workflow/agent/passthrough; automation exposes those namespaces and workflow resources; full exposes both. This verifies source contracts, not live deployment/authentication or successful backend runs.
