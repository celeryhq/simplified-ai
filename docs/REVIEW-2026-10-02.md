# Technical documentation review — October 2, 2026

## Scope and changes

Reviewed the repository entry points, asset intake guidance, image/video generation skills, client setup, and contributor evaluations against the local `simplified-apikit` main source and official client documentation.

| Finding | Change |
|---|---|
| Uploaded media could only be used by known UUID | Added `manage-assets` for `api_listAssets` listing/name-tag search, pagination, readiness, import/upload, and handoff |
| Image skill taught provider-specific reference names and stale model IDs/defaults | Rewrote around normalized `parameters.reference_images`, discovered IDs, explicit asset storage, and actual result envelopes |
| Video docs assumed submission/polling rather than middleware completion | Documented blocking generation, normalized UUID slots, and conditional continuation including failure/timeout envelopes |
| Chat attachments assumed byte PUT capability | Added a capability check before signing and a user-upload/downloadable-URL fallback |
| Reusing a transient image required an unstated conversion | Added URL import → ready UUID → social draft flow |
| One JSON setup snippet presented as universal | Added client-specific Codex TOML/CLI, Claude Code, ChatGPT, and other-client instructions |
| Old inventories/tool counts presented as current | Removed current-count promises from user entry points and labeled snapshots as historical |
| Contributor checks omitted asset skill | Added its frontmatter/metadata/contract checks and media evaluation scenarios |

## Evidence and limits

The existing baseline contract suite passed despite stale generation instructions. An independent read-only review identified the six scenario failures documented in `evals/media-scenarios.md`; rereading the revised instructions resolved those findings and identified the video envelope distinction, which was then added.

Contract checks, relative-link checks, and the ChatGPT skill bundle build were run on the revised tree. These validate documentation structure and packaging. They are not authenticated connector tests or empirical end-to-end agent execution. Historical hosted inventories remain untouched. No generation credits were spent, no customer assets were accessed, and no social content was published.

The legacy raw-image I/O harness still needs a separate implementation update before its historical results can be used to claim current MCP behavior. Deployment availability and app-directory listing must be checked in the client rather than inferred from the skill repository.
